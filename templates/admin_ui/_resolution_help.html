Element names, separated by commas, tried in order. How it works

For every redirect, the resolver looks at the requested ARK, part or variant and uses the first of these elements that has a value there. Names are upper-cased; give one to five. The legacy service used URL, WHERE?.

SettingBound on utsc1/ark:/61220/utsc1 goes to
URL, WHERE?URL = https://a.example/1
WHERE? = https://b.example/1		https://a.example/1
URL, WHERE?only WHERE? = https://b.example/1https://b.example/1
TARGET, URLTARGET = https://t.example/1
URL = https://a.example/1		https://t.example/1
TARGETonly URL = https://a.example/1404: URL is no longer used

A part such as utsc1/page2 uses the elements bound at /page2 itself, in the same order.

Path endings, separated by commas, that return JSON instead of redirecting. How it works

When a request ends in one of these segments, the resolver fetches the URL and returns its JSON (for IIIF viewers) instead of redirecting. It uses the URL bound at that ending, else the URL of what it is attached to. Each ending is one plain word: no / . ? # % - or spaces, and not starting with a digit or _. Leave empty for none.

SettingRequestAnswer
manifest/ark:/61220/utsc1/manifestJSON from the URL bound at /manifest; if none, from utsc1's URL
manifest/ark:/61220/utsc1/page2/manifestJSON from /page2/manifest, else from /page2
manifest, iiif/ark:/61220/utsc1/iiifJSON from the URL bound at /iiif, else utsc1's
(empty)/ark:/61220/utsc1/manifestan ordinary redirect to the URL bound at /manifest
manifest/ark:/61220/utsc1/manifest?the metadata of /manifest, nothing fetched
{% elif setting == "suffix_passthrough" %}
Let parts without their own URL borrow one. How it works

When ticked, a part with no URL of its own redirects to the nearest bound part above it, plus the rest of the path. A part with its own URL always uses it. Metadata (?, ??, ?info) and proxied endings are not affected. The cost: a mistyped part reaches the target site's "not found" page instead of ours. Unticked, an unbound part is a 404, as in the legacy service.

With utsc1 → https://site.example/utsc1 and utsc1/chapter2 → https://other.example/ch2:

The redirect is counted against the part that supplied the URL (utsc1 or chapter2).
